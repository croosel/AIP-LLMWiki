# 经验累积 SOP（2026-06-21 版）

> **核心**：错误是经验的高价值原料，不是负担
> **目的**：让每一次失败、每一个决策、每一条经验都能沉淀下来，让下一次 Agent 起点比当前更高
> **元原则**："所有决策、所有经验都应该累积"（主人 12:45 原话）

---

## §1 触发场景

| 场景 | 触发条件 | 优先级 |
|------|----------|--------|
| Agent 越界事件 | 任何 Agent 超出派发范围写入 | P0 |
| 规则升级 | 现有规则被事件打破 | P0 |
| 工具限制发现 | 沙箱/平台/工具能力发现新限制 | P1 |
| 决策点 | 主人拍板的关键决策 | P1 |
| 主人新规则 | 主人新增/修正行为规则 | P0 |
| 主人新愿景 | 主人立 flag / 目标 | P1 |
| Qoder 风格观察 | 其他 Agent 的高质量产出 | P1 |
| 元原则违反 | 错就改环节触发 | P0 |

## §2 5 步累积链路

### 步骤 1：事件记录（写完整链路）
- **动作**：按时间顺序记录事件背景、触发条件、过程、产出
- **格式**：`EXP-{主题}-{YYYYMMDD}.md`
- **必备字段**：
  - 触发场景（具体时间、命令、上下文）
  - 各方动作（A 做了什么 / B 回应什么 / 主人拍板什么）
  - 关键证据（命令、输出、commit hash）
- **参考案例**：`/老道产出/Qoder越界事件完整链路-20260621.md`

### 步骤 2：损伤评估（多维分析）
- **维度**：
  - **数据损失**：是否覆盖了已存在内容？是否能恢复？
  - **规范污染**：是否违反守门规则？污染了哪些页面？
  - **链接错乱**：是否产生死链 / 重复链接？
  - **决策负担**：是否给主人增加了拍板次数？
- **结论**：损伤等级 = 轻微 / 中等 / 严重 / 不可逆

### 步骤 3：决策（保留 / 回滚 / 升级）

| 决策 | 适用 | 原则 |
|------|------|------|
| **保留** | 错误产出有价值（如 Qoder 越界但产出了 302 行高质量内容） | 价值 > 损伤 |
| **回滚** | 错误产出无价值 / 严重污染规范 | 规范 > 价值 |
| **升级** | 事件暴露规则漏洞，必须补规则 | 防再发 + 累积 |

**Qoder 越界事件决策**（2026-06-21 12:51）：
- 不删除（保留作为决策证据 + 学习原料）
- 升级规则：v1 → v1.1（5 个补丁：派发状态机 / 等任务硬规则 / Agent 类型标注 / 派发检查清单 / 越界事件处理流程）
- 写完整链路 → `/老道产出/Qoder越界事件完整链路-20260621.md`

### 步骤 4：经验提炼（抽象到可复用规则）
- **方法**：
  - 错误模式 → 反模式清单
  - 修复方案 → 操作 SOP
  - 跨场景引用 → 适用范围 + 限制条件
- **格式**：
  - `### EXP-N | {一句话总结}`
  - 触发场景 / 错误模式 / 修复方案 / 跨场景引用 / 关键引述
- **沉淀位置**：
  - 试错日志：`/LLM-Wiki-日志/YYYY-MM-DD-试错日志-{Agent名}v{N}.md`
  - 经验索引：`wiki/经验索引.md` 4 处（方法论 / 决策经验 / 关键规则 / Agent 检查点）
  - 元页面：本 SOP

### 步骤 5：跨场景引用（让下次 Agent 直接复用）
- **动作**：
  - 在 [[经验索引]] 登记"我写了 XX"
  - 在相关页面（守门规则、Qoder 风格、苏格拉底老道）加交叉链接
  - 在 [[Agent工作流协议]] 附录 B「近期写入」表登记
- **关键**：经验不被引用 = 没沉淀。下次 Agent 不会主动看 = 等于不存在

## §3 不触发场景（节省老道精力）

| 不触发 | 原因 |
|--------|------|
| 纯读取任务 | 没有写入/决策 |
| 格式微调（typo 修复、换行） | 价值 < 累积成本 |
| 完全重复内容 | 已有 EXP 覆盖 |
| 失败但无教训 | 罕见但确实没教训 |
