## 1. 目的

让所有 Agent（老道 / Claude / Cursor / 其他任何 AI Agent）能**安全、并发、可追溯**地共同写入 [[AIP-LLMWiki]] vault，避免数据丢失、规范污染、链接错乱。

---

## 2. 核心规则（3 层守门）

### 层 1：粒度拆分（不重叠）

- 每个 Agent 只在自己负责的子目录 / 页面写
- 写前必须 `ls` + `read_file` 看目标文件最新状态
- **禁止**两个 Agent 同时写同一个文件
- 适用：所有写入场景

### 层 2：写入前必查（read_file 必先于 write_file）

- 任何写操作前必须 `read_file` 拉最新版
- 重要页面（>100 行）写前先 `cp` 到 `wiki/.bak/` 备份
- 写完用 `cat` 校验内容正确
- 适用：所有写入场景

### 层 3：写后必登记（让其他 Agent 知道）

- 每次写完在 [[经验索引]] 登记"我写了 XX"
- 重大写入同步更新 [[Agent工作流协议]] 的"近期写入"表格
- 链接规范：[[WikiLinks]] 不带 .md 后缀、不带 `\\`
- 新页面至少链接 2 个已有页面
- 适用：所有写入场景

---

## 3. 可选第 4 层：写入锁（高强度场景）

- 写时创建 `.lock` 隐藏文件
- 其他 Agent 看到 `.lock` 跳过该文件，等 30 秒后再读
- 写完删除 `.lock`
- 适用：>500 行的长页面、Agent-Handoff 接力场景、Schema 文件

---

## 4. 冲突矩阵对照表（为什么需要 3 层守门）

| 冲突类型 | 没守门会怎样 | 哪层守门解决 |
|---|---|---|
| 并发写入覆盖 | A 写 §3 被 B 写 §5 覆盖 | 层 1（粒度拆分） + 层 4（写入锁） |
| 规范不一致 | A 写 `[[X.md]]`，B 写 `[[X]]`，风格乱 | 层 2（写入前必查 AGENTS） |
| 职责重叠 | A 和 B 都写 OPC 页面，内容重复 | 层 1（粒度拆分） + 层 3（写后登记） |
| 链接错乱 | A 写时 `[[X]]`，B 删了 X，死链 | 层 2（写入前查 Wiki） + 层 3（写后登记） |
| 数据丢失 | B 覆盖 A，没法恢复 | 层 2（写前 .bak 备份） |

## 5. 违规处理

| 违规类型 | 处理方式 |
|---|---|
| 违反层 1（同时写同一文件） | 立即停止；老道先写完 → 对方 Agent 读最新版再写 |
| 违反层 2（没 read 就 write） | 回滚到上次备份（wiki/.bak/），重新 read + write |
| 违反层 3（没登记） | 补登记，写入 [[Agent工作流协议]] 近期写入表 + [[经验索引]] |
| 重复违反 | 写 [[EXP-XXX-YYYYMMDD]] 经验记录 + 通知主人 |
