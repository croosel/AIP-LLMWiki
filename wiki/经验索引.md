## 关键规则提炼
> 以下为跨多条经验提炼出的最高优先级规则，Agent 执行任务时应优先遵守。
1. **未经验证的成功是最大的失败** — 来源：[[LILIS_Execution_PostMortem_ImageReplace_20260524]]。任何操作完成后必须通过独立渠道验证结果，不可依赖系统返回的表面成功状态。
2. **执行前必须查 Wiki** — 来源：[[认知先行与目标趋近方法论]]。每次执行任务前，先检索知识库中的历史经验和方法论，避免重复犯错。
3. **P0 路径需三重证据** — 来源：[[最短时间执行路径方法论]]。对最高优先级的执行路径，需要文档证据、API 验证、实际数据三重确认后方可行动。
4. **Wiki 注入使输出质量提升 20 倍** — 来源：[[PAP实验A-B测试结果]]。将结构化 Wiki 知识注入 Prompt，可将 Agent 输出质量从 5% 提升至 100%。
5. **品牌配色以线上代码为准** — 来源：[[EXP-LILIS品牌Logo设计-20260613]]。Wiki 设计文档可能与实际代码严重脱节，品牌视觉规范应以线上代码（globals.css）为唯一真实来源。
6. **ICBU 产品管理走 Open Platform API，不走 Accio MCP** — 来源：[[EXP-ICBU开放平台API产品管理-20260614]]。Accio MCP 三重铁壁已封堵，但 ICBU Open Platform API 完全可用。schema.add 必须用 itemSchema 格式，图片必须先上传到图片银行。
7. **schema.add 前必须先 schema.render** — 来源：[[EXP-ICBU开放平台API产品管理-20260614]]。不要猜测字段名和类型，必须从 schema.render 获取目标分类的完整字段模板。
8. **运营层归 Agent，工程层归 Agent IDE** — 来源：[[EXP-独立站359产品批量上架-20260614]]。数据处理/清洗/QC 审计由 Agent 负责，代码修复/构建/部署由 Agent IDE 负责。Vercel CLI 直推适合快速验证但不符合第一性原理（无 Git 回滚、无 CI/CD）。
9. **代码阻断项应在工程层修复，不在运营层** — 来源：[[EXP-独立站359产品批量上架-20260614]]。ProductCard/PDP 的 Package 图标占位符是开发阶段技术债，应由 Agent IDE 在 IDE 环境中修复，Agent 不应越界写前端代码。
10. 🆕 **错误是经验的高价值原料，不是负担** — 来源：[[苏格拉底老道]] 元原则 + 主人 12:45 强化。所有决策、所有经验都应该累积。错误的产出 → 保留 + 升级规则 + 写完整链路，而不是删除。
11. 🆕 **老道自己排优先顺序，禁列 A/B/C/D** — 来源：[[苏格拉底老道]] v1.2 §4.3 主人 13:23 新规则。一次只给一件最重要的（说"为什么排第一"+"已经在做什么"），执行完再推下一件。
12. 🆕 **commit + push 才是真闭环，upload ≠ push** — 来源：[[EXP-苏格拉底老道原则立flag-20260621]] §3.5 元原则 v1.2 强化。写完 = 上传项目空间 ≠ 写完 = 远端 git tree。必须三层验证：(1) 写本地 (2) 上传项目空间 (3) 远端 git tree。
## Agent 执行检查点
任何 Agent 在开始工作前，应完成以下三步检查：
- [ ] **第一步：查索引** — 查阅本页面（[[经验索引]]），判断是否有与当前任务相关的历史经验
- [ ] **第二步：读经验** — 如有相关经验，打开对应经验页面，仔细阅读背景、执行路径、结果和经验提炼，理解前车之鉴
- [ ] **第三步：记经验** — 任务完成后，按 [[经验记录模板]] 创建新的经验记录页面，并更新本索引
- [ ] 🆕 **第四步：复述三原则** — 复述苏格拉底老道 1 句话："剥到底，推到端，元审视"
- [ ] 🆕 **第五步：守门规则** — 写入前确认遵守 3 层守门（层 1 粒度 + 层 2 必查 + 层 3 必登记）
- [ ] 🆕 **第六步：自排优** — 多任务时自己按剥/推/元排优，禁列 A/B/C/D 让主人拍板
