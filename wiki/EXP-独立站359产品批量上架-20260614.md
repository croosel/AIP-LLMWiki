# 独立站 359 产品批量上架实战经验

## 背景
- **目标**: 从阿里巴巴国际站（ICBU）批量复制 359 个产品到 lilisaura.vercel.app 独立站
- **Agent**: Agent（运营层） + Agent IDE（工程层，待实施）
- **时间**: 2026-06-14
- **上下文**: 独立站已有 6 个 Demo 产品和完整 Next.js 代码框架，需扩展为 359 个真实产品

## 执行路径

### 选择的方法
采用 ICBU Open Platform API 导出 → ETL Pipeline 处理 → 静态 JSON 数据注入的路线。

### 替代方案（未选）
- **页面爬取**：违反平台 ToS，且数据结构不稳定，放弃
- **手动录入**：359 个产品人工录入效率极低，放弃
- **CSV 手动导入**：需要先有数据源，ICBU 后台不提供完整 CSV 导出

### 关键步骤
1. **ICBU API 数据导出**：调用 `alibaba.icbu.product.list` + `alibaba.icbu.product.get`，获取 359 个产品完整数据
2. **ETL Pipeline 处理**：字段映射（18 个字段）、Description 两遍清洗（去 boilerplate + 补空）、79 个未分组产品关键词分类
3. **资产准备**：下载 359 张产品图 + 10 张分类图、生成 inventory.json（718 条双仓库记录）
4. **代码修复**：ProductCard 图片渲染、PDP 图片画廊+面包屑、inventory.json 真实 ID
5. **部署验证**：Vercel CLI 部署 → 浏览器自动化验证全部 10 个品类页 + PDP

## 结果

- 359 个产品全部上架，覆盖 10 个品类（flowers:129, garlands:66, balloons:52, floral-walls:37, tableware:32, backdrops:20, lighting:10, party:7, drapery:6）
- 每个产品有：真实图片、三级价格、双仓库库存、面包屑导航
- Vercel 部署状态 Ready，构建 40 秒完成

- 品类抽样：balloons(52) + tableware(32) + backdrops(20) + party(7) = JS DOM 计数确认

## 经验提炼

### 核心教训
**Vercel CLI 直推是"手工作坊"，Agent IDE 工程化部署才是"工业流水线"** — 前者快但无 Git 回滚、无 CI/CD、无代码审查，后者符合第一性原理。

### 可复用规则
1. **ICBU 产品数据必须走 Open Platform API**：`product.list` 只给元数据，`product.get` 才有完整详情（定价/规格/库存）
2. **Description 清洗必须两遍**：第一遍去 Alibaba 模板 boilerplate，第二遍补空描述（84 个产品原描述为空）
3. **未分组产品用关键词 fallback 分类**：79 个无 group_name 的产品通过 11 条正则规则全部分入品类
4. **代码阻断项应在工程层修复**：Agent 的强项是运营（数据处理），不是写前端代码
5. **inventory.json 必须用真实产品 ID**：Demo 数据的假 ID ("1"-"6") 会导致全站库存显示为 0

### 避坑指南
- `product.list` API 返回的 `subject` 不等于完整 title，需从 `product.get` 获取
- `--dry-run` 模式仍会写入文件，测试时务必备份 products.json
- ICBU 签名算法是 HMAC-SHA256，参数必须按字母序排列后拼接
- 本地 Next.js build 可能因内存限制 SIGBUS，部署应交给 Vercel 服务器
