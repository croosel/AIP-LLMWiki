# OPC 独立站建站自动化分析与 SOP 制定

## 背景
- **目标**: 用第一性原理分析 Agent（Agent）是否适合做独立站建站自动化；制定完整的独立站建站 SOP；在 AI 员工架构中增设独立站建站总监角色
- **Agent**: Agent
- **时间**: 2026-06-12
- **上下文**: OPC 双轨出海项目已完成商业模式设计、可行性分析、AI 员工架构（14-17 Agent），但缺少独立站建站这个关键模块。用户要求用第一性原理思考 Agent 是否是最优选择，并增设建站总监。

## 执行路径
- **选择的方法**: 第一性原理分析 — 将建站拆解为五层原子工作（需求收集、技术搭建、内容填充、SEO/GEO、持续运维），逐项评估 Agent 能力，对比替代方案
- **替代方案**: 
  - 独立站 手动操作（无法规模化）
  - 纯编程方案 独立站 Hydrogen（过度工程）
  - 外包建站公司（成本不可控）
  - PageFly/Shogun 页面构建器（工具层面，不影响编排决策）
- **关键步骤**: 
  1. 拆解建站为 30+ 个原子工作项，按五层分类
  2. 审计 Agent 的实际能力（16 个浏览器工具 + 代码生成 + 内容生成 + 定时任务等）
  3. 识别能力边界（高端视觉设计、物理摄影、复杂 UX 需其他工具补充）
  4. 得出结论：Agent 是最优编排中枢，但不是唯一工具
  5. 设计工具链分工（编排层/内容层/技术层/图片层/数据层/设计层）
  6. 编写五阶段建站 SOP（需求收集→信息架构→技术搭建→内容填充→上线交付）
  7. 增设独立站建站总监（含建站组、SEO/GEO 组、运维组），AI Agent 总数从 14-17 调整为 17-21

## 结果
- **实际结果**: 
  - 完成第一性原理分析文档（含原子拆解、能力审计、替代方案对比、规模化路径）
  - 完成独立站建站 SOP（含客户需求收集表、品牌资产清单、技术 Checklist、SEO/GEO 配置、质量验收标准）
  - AI 员工架构新增独立站建站总监 + 3 个下属组（建站组、SEO/GEO 组、运维组）
  - 更新了项目文件（01_AI员工化架构设计.md）和 4 个 Wiki 页面
- **验证方式**: 文件内容审查（确认所有 wikilink 正确、Agent 数量一致）
- **与预期对比**: 预期是分析 Agent 适配度 + 出 SOP + 改架构，三项全部完成

## 经验提炼
- **核心教训**: 独立站建站本质上是「编排任务」而非「编程任务」或「设计任务」。它需要从非结构化输入生成结构化输出，并协调多个平台。这正是 Agent 最强的能力组合。
- **可复用规则**: 
  1. 评估工具适配度时，先拆解工作为原子级，再逐项评估，避免笼统判断
  2. SEO/GEO 应该是建站的「基础设施」而非「后期补充」，所以归建站总监而非运营总监
  3. 建站 SOP 必须覆盖「隐性需求」（客户不会主动提供的信息，如库存管理方式、退货政策、季节性计划）
- **避坑指南**: 
  - 浏览器自动化操作 独立站 可能因 UI 更新而中断，应优先使用 独立站 API
  - 第一个客户建站必须投入足够时间建立可复制模板，这是「建一个能建网站的系统」而非「建一个网站」
