# 优品清单 API 批量提取

## 背景
- **目标**: 从阿里巴巴国际站卖家后台提取「优品清单」22 件产品的主题照片、商品ID、商品链接、价格、MOQ，输出为 Excel
- **Agent**: QoderWork
- **时间**: 2026-06-26
- **上下文**: 用户给出产品成长工作台 URL（hz-productposting.alibaba.com/product_operate/product_growth.htm），要求提取优品分类下的全部产品数据。最初尝试浏览器逐页翻取，效率极低，用户指出应使用已记录的 API 方法

## 执行路径
- **选择的方法**: 通过 ICBU Open Platform API `alibaba.icbu.product.get` 逐个拉取产品详情，Python 脚本批量处理，openpyxl 生成含嵌入图片的 Excel
- **替代方案**: 
  - 浏览器自动化逐页截图+OCR（放弃：10+ 分钟只能处理几页，用户明确否决）
  - `product.list` 批量查询（放弃：list 只返回摘要字段，不含主图 URL 和详细价格）
- **关键步骤**: 
  1. 从 Wiki 找到已记录的 ICBU API 凭据和技术手册
  2. 用 `product.list` 先获取全部产品 ID，筛选优品分类
  3. 用 `product.get` 逐个拉取 22 件优品完整详情
  4. 解析 JSON 响应，提取主图/价格/MOQ/链接
  5. 下载主图 → 缩略图 → openpyxl 嵌入 Excel

## 结果
- **实际结果**: 成功提取全部 22 件优品数据，生成含主题照片的 Excel 文件
- **验证方式**: Excel 打开确认 22 行数据完整，图片正确嵌入，价格/链接可点击
- **与预期对比**: 超出预期——API 方式几秒完成全部提取，比浏览器方案快 100 倍以上

## 经验提炼

### 核心教训

**product.get 响应字段结构与直觉不同**，不能靠猜，必须 dump 原始 JSON 探索。

### product.get 响应字段映射（已验证）

| 需要的数据 | JSON 路径 | 备注 |
|-----------|-----------|------|
| 产品标题 | `product.subject` | 直接取值 |
| 主图 URL | `product.main_image.images.string` | **不是** `product.image.images.image` |
| 价格 | `product.wholesale_trade.price` | 字符串，如 "1.08~1.98" |
| 价格单位 | `product.wholesale_trade.unit_type` | 如 "Piece"、"Set" |
| MOQ | `product.wholesale_trade.deliver_periods.deliver_period[0].quantity` | 无直接 MOQ 字段，用交期起量近似 |
| 产品链接 | `product.pc_detail_url` | PC 端详情 URL |
| SKU 阶梯价 | `product.product_sku.skus.sku_definition[].bulk_discount_prices` | 可选，更精细的价格 |
| 产品分组 | `product.product_group.group_name` | 如 "Premium Floral Art" |

### 踩坑记录

#### 坑 1: 浏览器逐页翻取效率极低（流程错误）

**现象**: 用浏览器自动化打开产品成长工作台，一页页翻取产品数据，10+ 分钟只处理了几件。

**根因**: 浏览器方案本质是 O(n) 人工操作，没有利用已有的 API 基础设施。

**解决**: 用户指出后切换到 ICBU Open Platform API，几秒完成全部 22 件提取。

**规则**: **有 API 可用时，永远不要用浏览器 scraping。API 是 O(1) 基础设施，浏览器是 O(n) 手工操作。**

#### 坑 2: product.get 响应字段路径与文档不一致（隐蔽）

**现象**: 按直觉猜测 `product.image.images.image` 取主图，返回空。

**根因**: 实际路径是 `product.main_image.images.string`，字段名和结构都与预期不同。ICBU API 没有完整的响应字段文档。

**解决**: dump 原始 JSON 响应，用 Python 递归遍历所有 key 找到正确路径。

**规则**: **ICBU product.get 的响应字段必须通过 dump 原始 JSON 确认，不要猜字段名。**

#### 坑 3: MOQ 没有直接字段（隐蔽）

**现象**: 遍历 product.get 响应找不到名为 "moq" 或 "minOrderQuantity" 的字段。

**根因**: product.get 的响应中没有直接暴露 MOQ。最接近的代理字段是 `wholesale_trade.deliver_periods.deliver_period[0].quantity`（交期对应的起始数量）。对于 RTS（Ready to Ship）产品，默认 MOQ=1。

**规则**: **MOQ 用 deliver_periods[0].quantity 近似，RTS 产品默认 1。**

#### 坑 4: SSL 证书验证失败（环境）

**现象**: macOS 本地 Python `urllib` 调用 ICBU API 报 `CERTIFICATE_VERIFY_FAILED`。

**根因**: macOS 系统 Python 未安装根证书。

**解决**: `ssl.create_default_context()` + `check_hostname=False` + `verify_mode=CERT_NONE`。

**规则**: **macOS Python 调外部 API 必须禁用 SSL 验证或使用 certifi。**

### 可复用规则

1. **API 优先原则**: 有 API 可用时，绝不用浏览器 scraping
2. **dump 原始响应**: ICBU API 响应字段靠 dump 确认，不靠猜
3. **product.get 字段映射**: 主图=`main_image.images.string`，价格=`wholesale_trade.price`，MOQ≈`deliver_periods[0].quantity`
4. **Excel 嵌入图片**: openpyxl + Pillow 组合，图片先缩放到 80x80 再嵌入

### 避坑指南

下次提取 ICBU 产品数据时：

1. **不要浏览器翻页面** — 先用 API，`product.list` 拿 ID 列表，`product.get` 拿详情
2. **不要猜字段名** — dump 一个完整的 product.get 响应，递归打印所有 key
3. **不要找 MOQ 字段** — 没有直接的 MOQ，用 deliver_periods 近似
4. **不要忽略 SSL** — macOS 上必须加 SSL context bypass
